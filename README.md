# مدار — إدارة الموظفين والمهام ووقت العمل

مدار تطبيق عربي لإدارة فريق العمل داخل الشركة: الموظفون والأقسام، والمشاريع والمهام، وسير المراجعة والاعتماد، ووقت العمل الفعلي المسجّل بالمؤقت، والتقارير. يعمل كموقع ويب متجاوب وكتطبيق موبايل (Expo / React Native) من الكود نفسه.

يعمل مدار بنظام **متعدد الشركات**: حساب مطوّر واحد يدير المنصة ويضيف الشركات، وكل شركة لها نظامها الكامل وبياناتها المعزولة تمامًا.

- **الموقع:** يُنشر على Vercel من فرع `main`.
- **قاعدة البيانات والمصادقة والملفات:** Supabase (المشروع `ppihzxabbysozbdmweje`).

## أول تشغيل

1. افتح الموقع. إذا لم يكن هناك حساب مطوّر بعد، تظهر شاشة **«إعداد حساب المطور»**.
2. أدخل اسمك وبريدك وكلمة المرور. يصبح هذا الحساب **حساب المطور** (الأكونت الأم)، ولا يمكن تكرار هذه الخطوة بعد ذلك.
3. من صفحة **الشركات** يرى طلبات العملاء (شركات بانتظار الموافقة) ويوافق عليها أو يرفضها، ويستطيع أيضًا إضافة شركة مباشرة دون انتظار، مع حساب **مدير نظام** لها (اسم وبريد وكلمة مرور).
4. العميل يسجّل شركته من صفحة الدخول (**تسجيل شركة جديدة**: اسم الشركة والمنطقة الزمنية)، فيصل الطلب لحساب المطور. بعد الموافقة تُفعّل الشركة وحساب مديرها ويستطيع الدخول.
5. سلّم بيانات مدير الشركة له؛ يسجّل الدخول فيجد نظام الشركة كاملًا: الأقسام، الفريق، المشاريع، المهام، التقارير.
6. يضيف مدير الشركة الأقسام من **الأقسام**، ثم الموظفين من **الفريق**.

كل شركة معزولة على مستوى قاعدة البيانات: لا يرى مستخدمو شركة أي بيانات من شركة أخرى، وحساب المطور لا يدخل تفاصيل مهام الشركات، بل يرى لوحة الشركات وتقاريرها المجمّعة. صفحة الدخول مخصّصة لعملاء الشركات، ولحساب المطور شاشة دخول مستقلة عبر رابط **«دخول حساب المطور»** أسفلها.

## حساب المطور والتقارير

- **صفحة الشركات:** كل شركة في كرت واحد ببياناتها المجمّعة (الأعضاء النشطون، الأقسام، المهام المفتوحة والمتأخرة، الوقت المسجّل)، ومعها رابط دعوة الموظفين وكوده، وتوليد كود جديد يبطل الرابط القديم، وإيقاف/تفعيل الشركة، وتعيين كلمة مرور مديرها.
- **تقارير الشركات:** صفحة مستقلة تجمع كل الشركات مع فلاتر (نشطة/موقوفة) وبحث، وتُظهر مؤشرات كل شركة على حدة، وتصدّر كل الصفوف إلى CSV.
- **إيقاف الشركة:** يمنع الدخول لأي حساب داخلها ويغلق صفحة الدعوة، مع شاشة توضيحية للمستخدمين.

## رابط دعوة الموظفين

لكل شركة رابط عام بصيغة `/join/<code>` يعرض اسم الشركة. من يفتحه ينشئ حسابه فيصل طلبه إلى مدير الشركة كـ«بانتظار الموافقة»، إلا إذا كان بريده مسجّلًا في تصريح سابق فيُفعّل تلقائيًا بدوره وقسمه. يمكن توليد كود جديد من حساب المطور لإبطال الرابط القديم.

## الأشهر والمهام الشهرية

المهام مرتبطة بشهر (`company_months`). الشهر الحالي يُفتح تلقائيًا، ويمكن لمدير الشركة إغلاقه يدويًا أو يُغلق تلقائيًا مع بداية الشهر التالي. الشهر المغلق يصبح أرشيفًا للقراءة فقط: لا إضافة أو تعديل أو حذف لمهامه، وتظهر بياناته في تقارير الشركة والموظف.

## الأيام والمهام اليومية

داخل كل شهر دورة يومية (`company_days`): لكل مهمة **يوم تنفيذ**، وكل يوم يُغلق تلقائيًا في منتصف الليل بتوقيت الشركة أو يغلق مبكرًا بزر **«إغلاق اليوم»** من مدير الشركة، ثم يُفتح يوم جديد. المهام التي لم تكتمل تبقى في أرشيف يومها وتظهر كمتأخرة دون ترحيل تلقائي.

- شاشة المهام تبدأ بمهام اليوم، ومعها تقويم الشهر لاختيار أي يوم وفتح مهامه أو إنشاء مهام فيه.
- كل مهمة لها زر **«إنهاء»**: يرسلها للمراجعة، أو يغلقها مباشرة إن كانت مهمة شخصية بلا مراجع.
- اليوم المغلق للقراءة فقط: لا تعديل ولا تعليقات ولا مؤقت ولا مهام جديدة، ويستثنى قرار المراجع (اعتماد أو إعادة) للمهام التي كانت بانتظار المراجعة.
- إغلاق الشهر يغلق كل أيامه المفتوحة، وفتح شهر جديد يفتح أيامه يومًا بيوم.

## الأدوار والصلاحيات

| الدور | الصلاحيات |
| --- | --- |
| حساب المطور | إدارة المنصة: إضافة الشركات وحسابات مديريها، إيقاف/تفعيل الشركات، روابط الدعوة، وتقارير مجمّعة لكل شركة — دون الدخول إلى تفاصيل مهامها |
| مدير النظام | كل شيء داخل شركته: الأقسام، الأدوار، تفعيل الحسابات وإيقافها، إعدادات الشركة |
| مدير قسم | أعضاء قسمه ومشاريعه ومهامه، وإضافة موظفين لقسمه وتعيين كلمات مرورهم |
| مشرف | إنشاء مهام القسم وإسنادها ومراجعتها |
| موظف | المهام المسندة إليه أو التي أنشأها، والمؤقت، والتعليقات والمرفقات |
| مشاهد | قراءة فقط |

القواعد مطبّقة داخل قاعدة البيانات نفسها (Row Level Security ومشغّلات وقواعد RPC)، وليس في الواجهة فقط. لا يستطيع أي موظف تغيير دوره أو قسمه، ولا يمكن إزالة آخر مدير نظام في أي شركة، وكل صف مربوط بشركته.

## إضافة الموظفين

- **حساب بكلمة مرور:** يُنشأ الحساب مفعّلًا فورًا بكلمة مرور مؤقتة تسلّمها للموظف.
- **تصريح بالتسجيل:** تُسجّل بريد الموظف مع دوره وقسمه، ثم يسجّل هو بنفسه من «اطلب الانضمام» ويُفعّل تلقائيًا.
- **طلب انضمام:** أي شخص يسجّل بدون تصريح يبقى «بانتظار الموافقة» حتى يفعّله مدير النظام من صفحة الفريق.

> لا يُرسل التطبيق رسائل بريد إلكتروني؛ شارك بيانات الدخول أو رابط الموقع مع الموظف بنفسك.

## الميزات

- لوحة رئيسية حسب الدور: المهام المفتوحة والمتأخرة وبانتظار المراجعة وساعات الأسبوع وحمل العمل على الفريق.
- المهام: عدة مسؤولين، مراجع، أولوية، تواريخ، وقت مقدّر، مهام فرعية، تعليقات، مرفقات خاصة، وسجل نشاط.
- عروض المهام: جدول، كانبان، تقويم، وجدول زمني.
- سير العمل: جديدة ← قيد التنفيذ ← بانتظار المراجعة ← مكتملة، مع الإعادة للتنفيذ بملاحظة، والتعليق، وزر إنهاء في كل مهمة.
- الأيام: مهام اليوم وتقويم الشهر، وإغلاق اليوم تلقائيًا أو يدويًا، وأرشفة المهام غير المكتملة كمتأخرة.
- المؤقت: جلسة واحدة جارية لكل موظف على مستوى الخادم، مع إضافة وقت يدوي.
- التقارير: ساعات العمل الفعلية يوميًا وحسب العضو والمشروع، ونسبة الالتزام بالمواعيد، وتصدير CSV.
- استيراد المهام من ملف CSV (من الإعدادات)، مع معاينة وتحقق من كل سطر.
- إشعارات داخل التطبيق: الإسناد، طلب المراجعة، الاعتماد، الإعادة، التعليقات، طلبات الانضمام.
- كل الأوقات تُخزّن بتوقيت UTC وتُعرض بالمنطقة الزمنية للشركة (من الإعدادات).

## التطوير المحلي

```bash
pnpm install
pnpm dev        # تشغيل Expo (الويب على المنفذ 8081، ويمكن فتحه في Expo Go)
pnpm check      # فحص الأنواع TypeScript
pnpm test       # اختبارات الوحدة (التوقيت، CSV، الصلاحيات)
pnpm build      # بناء نسخة الويب في dist
```

متغيرات اختيارية (لها قيم افتراضية تشير إلى مشروع Supabase الحالي):

```
EXPO_PUBLIC_SUPABASE_URL=https://ppihzxabbysozbdmweje.supabase.co
EXPO_PUBLIC_SUPABASE_KEY=<publishable key>
```

المفتاح المستخدم في الواجهة هو المفتاح العام (publishable) فقط. مفتاح الخدمة (service role) لا يوجد إلا داخل Edge Function على Supabase.

## بنية المشروع

```
app/                      شاشات Expo Router
  login.tsx               دخول العملاء، تسجيل شركة جديدة (بانتظار موافقة المطور)، طلب الانضمام، إعداد المطور
  developer.tsx           شاشة دخول حساب المطور
  join/[code].tsx         صفحة دعوة الموظفين العامة لكل شركة
  (app)/                  المنطقة المحمية: الرئيسية، المهام، المشاريع، الفريق، الأقسام، التقارير، الإشعارات، الشركات وتقارير الشركات (للمطور)، الإعدادات
components/madar/         مكوّنات الواجهة وهيكل التطبيق والنماذج وعروض المهام
lib/madar/                الأنواع، التسميات، التنسيق والتوقيت، الصلاحيات، طبقة البيانات، الجلسة، CSV

```

## قاعدة البيانات

الـ migrations في `supabase/migrations` هي المرجع الكامل، وكلها مطبّقة على المشروع:

1. `madar_schema` — الجداول والأنواع والفهارس.
2. `madar_logic` — المشغّلات (ترقيم المهام، سجل النشاط، الإشعارات، قواعد تغيير الحالة) ودوال المؤقت.
3. `madar_security` — سياسات RLS لكل جدول، ومساحة تخزين المرفقات الخاصة.
4. `madar_function_grants` — تقييد تنفيذ الدوال على المستخدمين المسجّلين.
5. `madar_developer_role` — إضافة دور «حساب المطور» إلى الأنواع.
6. `madar_companies` — جدول الشركات، وربط كل الجداول بـ `company_id`، وإعادة كتابة سياسات RLS والمشغّلات لتعزل كل شركة عن غيرها.
7. `madar_company_requests` — حالة `pending` للشركات التي يسجّلها العملاء بانتظار موافقة المطور.
8. `madar_months` — فترات شهرية لكل شركة، أقفال الكتابة على الأشهر المغلقة، ودوال فتح/إغلاق الشهر.
9. `madar_join_links_reports` — أكواد دعوة الشركات، صفحة الانضمام العامة، وإحصاءات وتقارير المطور.
10. `madar_task_days` — يوم تنفيذ لكل مهمة، جدول أيام الشركة، دوال فتح اليوم وإغلاقه تلقائيًا أو يدويًا، وأقفال الكتابة على الأيام المغلقة.
11. `madar_task_day_past_guard` — منع إضافة أو نقل المهام إلى يوم انتهى حتى لو لم يكن له صف أرشيف بعد.

لنشر Edge Function بعد تعديلها:

```bash
supabase functions deploy admin-users --project-ref ppihzxabbysozbdmweje --no-verify-jwt
```
